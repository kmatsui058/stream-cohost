# Design

## Context

- 実行環境は Windows 11 + Node.js 22。依存パッケージは `@google/genai`、`obs-websocket-js`、`ws`。外部プロセスとして ffmpeg を使う。
- 各モジュールは外部サービスを直接 import したり生成したりしているため、そのままでは単体テストできない。`src/gemini.js` の AI クライアントだけは注入できる。
- 画面側（`public/overlay.html`）は、ロジックが HTML にインラインで書かれていて、Node から読み込めない。
- `src/log.js` は、import した時点で `logs/` を作り、ファイルを開く。
- 仕様を書く過程で、次の不具合が見つかった。
  1. 発話の中断：合成を待っている間に中断され、直後に新しい文が来ると、古い再生ループが中断前の文を再生してしまう（speech-output「発話を中断する」）。
  2. チャットの切り替え：取得中に切り替えると、通信中だった古い取得が次の取得を予約してしまい、取得ループが 2 本並走しうる（live-chat「対象の配信を切り替える」）。
  3. OBS への初回接続：初回の接続に失敗したときの再試行が、ライブラリの切断イベント任せになっている。再試行される保証がなく、二重に予約される可能性もある（screen-capture「配信ソフトとの接続を自動で回復する」）。
  4. 要約中の発言：直近として残す件数が 0 のとき、要約中に届いた発言が要約対象の発言に結合され、その後まとめて削除される（conversation-memory「要約中に新しい発言が届く」）。

## Goals / Non-Goals

**Goals:**
- 仕様の全シナリオに、対応する自動テストがある。テスト名に、要件名とシナリオ名を含める。
- CI は、ネットワーク、API キー、ffmpeg、OBS、VOICEVOX のどれも無しで動く。
- 実機・実 API での確認は、手順化した手動スモークテストで行う。

**Non-Goals:**
- Lint やフォーマッタの導入（別の変更で検討する）
- TypeScript への移行
- 実 API を CI で呼ぶこと（課金と秘密情報の管理が増えるため）

## Decisions

### テストフレームワークは Vitest
- ESM のまま動き、フェイクタイマー（再接続の間隔、沈黙の秒数、タイムアウト）と、v8 によるカバレッジがそろっている。
- 代替案の `node:test` は追加依存が無い点で有利だが、フェイクタイマーとカバレッジの集計を自前でそろえる必要がある。

### 外部依存は、コンストラクタ引数で差し替えられるようにする
既定値は本番の実装のままにして、テストからだけ差し替える。外から見た振る舞いは変えない。

| モジュール | 注入するもの |
|---|---|
| mic | 子プロセスを起動する関数（既定は `child_process.spawn`） |
| obs | OBS クライアント（既定は `new OBSWebSocket()`） |
| gemini | AI クライアント（既存） |
| memory | AI クライアント（既存）、要約ファイルのパス |
| speaker | 合成関数（既定は `voicevox.synthesize`） |
| voicevox / youtube | `fetch`（既定はグローバルの `fetch`） |
| director | gemini、speaker、memory（既存）、現在時刻を返す関数 |

- 代替案はモジュールモック（`vi.mock`）。import の順序や巻き上げに依存して壊れやすく、本番コードの依存関係も見えにくくなるので採らない。

### 起動処理を「組み立て」と「エントリポイント」に分ける
- `src/config.js` は、環境変数とファイル読み込み関数を受け取って設定を返す純粋な関数 `loadConfig(env, readFile)` にする。
- `src/app.js` に `createApp(config, deps)` を置く。部品の生成・配線と、コマンドの処理 `handleCommand(line)` を担当する。
- `src/main.js` は、`.env` 由来の環境変数を読む、必須設定を確認する、`createApp` を呼ぶ、標準入力とシグナルをつなぐ、だけの薄い層にする。カバレッジの対象からは外す。

### ログは出力先を設定できるようにする
- `src/log.js` に `configureLogging({ dir, debug, toConsole })` を追加する。ファイルは最初に書き込むときに開く。
- テストでは一時ディレクトリに出すようにし、内容も検証できるようにする。

### 画面側のロジックを ES モジュールに分ける
- `public/overlay-core.js` に `createOverlayClient({ audioContext, connect, elements })` を置き、HTML からはこれを読み込むだけにする。
- テストでは、偽の AudioContext・WebSocket・要素オブジェクトを渡して、再生・字幕・口パク・完了通知・再接続を検証する。jsdom は使わない（Web Audio が無いので、結局偽物が必要になるため）。

### 不具合の直し方
1. 発話の中断：再生ループに世代番号を持たせる。中断で世代を進め、古いループは自分の世代が古くなっていたら何もせずに抜ける。
2. チャットの切り替え：取得ループにも世代番号を持たせる。応答が返ってきた時点で世代が古ければ、結果を捨てて次の取得を予約しない。
3. OBS への接続：再接続の予約を 1 か所にまとめ、予約済みなら重ねて予約しない。初回の失敗も、切断イベントも、同じ予約処理を通す。
4. 要約中の発言：要約の対象を「開始時点の発言の配列そのもの」として確定し、対象の最後の発言には以後の文字起こしを結合しない。

### カバレッジの閾値
- `src/` と `public/overlay-core.js` を対象とし、`src/main.js` は除く。
- 行と分岐の両方で 80% を下回ったら CI を失敗させる。

### CI は GitHub Actions
- `windows-latest` と `ubuntu-latest` のマトリクスで、Node 22 を使う。本番は Windows だが、パス区切りなどの OS 依存を早く見つけるため Linux でも回す。
- 手順：`npm ci` → `npx openspec validate --all --strict` → `npx vitest run --coverage`。
- OpenSpec の利用統計は、CI では `OPENSPEC_TELEMETRY=0` で無効にする。

### 手動スモークテスト
- `docs/smoke-test.md` に、実機・実 API での確認手順をチェックリストとして書く。対象は、VOICEVOX、OBS への接続とブラウザソース、マイク、Gemini との往復、張り直し（`r`）、チャット。
- Gemini API キーなどを正規に設定してから実施する。

## Risks / Trade-offs

- [テストの偽物が、実際の SDK や API の振る舞いとずれる] → 偽物は SDK の型定義（`LiveServerMessage` など）と同じ形にする。実際の振る舞いは手動スモークテストで確認する。
- [注入のためのリファクタリングで振る舞いが変わる] → 先にテストを書き、リファクタリングの前後で同じテストが通ることを確認する。
- [カバレッジ 80% が形だけの目標になる] → 閾値よりも、シナリオとテストの対応を優先する。tasks で、シナリオごとにテストを書く。
- [Windows のランナーは遅い] → マトリクスにして並列で走らせる。遅すぎれば Linux だけに減らす。

## Migration Plan

- 実行時の設定（`.env`）と使い方は変わらないので、移行作業は不要。
- 問題が出たら、変更前のコミットに戻せば元の状態に戻る。
