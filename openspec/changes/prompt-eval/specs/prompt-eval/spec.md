# Spec Delta

## Purpose

persona を変更したときに、同じ入力に対して相方がどう返事をするかを版ごとに並べて比べ、変更の効果を配信の前に確かめられるようにする。

## ADDED Requirements

### Requirement: 評価ケースを版ごとに実行する
システムは、評価ケースのそれぞれについて、今の persona と比較用の persona の両方で、同じ入力を AI に与えて返事を受け取らなければならない（SHALL）。比較用の persona は git の版で指定でき、指定がなければ既定の版を使わなければならない（SHALL）。あるケースで返事を受け取れなかった場合は、そのケースを失敗として記録し、残りのケースを続けなければならない（SHALL）。

#### Scenario: 2 つの版で実行する
- **WHEN** 15 個の評価ケースで評価を実行する
- **THEN** 各ケースについて、今の persona と比較用の persona の返事が 1 つずつ得られる

#### Scenario: 返事が返ってこない
- **WHEN** あるケースで、制限時間内に返事が返ってこない
- **THEN** そのケースは失敗として記録され、次のケースに進む

### Requirement: 返事をルールでチェックする
システムは、返事ごとに次の項目をチェックしなければならない（SHALL）。70 文字を超える長さ、疑問で終わるか、「ですね」の有無、サポート口調の言い回し、共感の定型句、自分の役割への言及、配信者を「オコハ」以外の名前で呼んでいないか。

#### Scenario: サポート口調の返事
- **WHEN** 返事が「了解しました。準備はよろしいですか。」である
- **THEN** サポート口調と、疑問で終わることが記録される

#### Scenario: 誤った呼び方
- **WHEN** 返事に「小波さん」が含まれる
- **THEN** 呼び方の誤りが記録される

### Requirement: 結果を書き出す
システムは、ケースごとに入力と両方の版の返事とチェック結果を並べた表と、版ごとのチェックの集計を、Markdown のファイルに書き出さなければならない（SHALL）。

#### Scenario: 評価が終わる
- **WHEN** 全ケースの実行が終わる
- **THEN** `eval/results/` に、ケースごとの比較表と、版ごとの集計が書かれたファイルができる
