# Spec Delta

## MODIFIED Requirements

### Requirement: 要約の作り方
システムは、要約を設定したモデル（既定 `gemini-3.8-flash`）で、設定した文字数（既定 4,000 文字）以内の日本語で作るよう求めなければならない（SHALL）。残すもの（配信で今やっていることと流れ、読み上げられた物語やセリフの要点、配信者が話した事実・好み・予定・感想、配信者や視聴者が教えてくれたことや訂正されたこと、相方とのやり取りで答えた内容、常連の視聴者とその特徴）と捨てるもの（相づち、挨拶の繰り返し、言い淀み、相方の仕組みの動作確認・設定・不具合のやり取り）を指示しなければならない（SHALL）。ペルソナ、今日の配信の情報、これまでの配信の要約を「すでに与えている情報」として添え、そこに書いてあること（配信者や相方の名前・設定、過去の配信の出来事など）を繰り返さないよう指示しなければならない（SHALL）。相方や配信者が過去の配信を振り返って話しただけの内容は、今回の出来事として残さないよう指示しなければならない（SHALL）。残すものがなければ「（なし）」とだけ返すよう指示しなければならない（SHALL）。要約が空で返った場合は失敗として扱い、記録と前回の要約を変えてはならない（MUST NOT）。

#### Scenario: 要約を求める
- **WHEN** 要約を作る
- **THEN** 設定したモデルに、4,000 文字以内であることと、残すもの・捨てるもの（動作確認のやり取りを含む）と、何もなければ「（なし）」とする指示が送られる

#### Scenario: すでに与えている情報は繰り返さない
- **WHEN** ペルソナに配信者の名前が書かれた状態で要約を作る
- **THEN** 要約の指示に、ペルソナと今日の配信の情報が「すでに与えている情報」として添えられ、そこに書いてあることを繰り返さないよう指示される

#### Scenario: 要約が空で返った
- **WHEN** 要約を求めた結果が空文字だった
- **THEN** 要約は失敗として扱われ、記録と前回の要約はそのまま残る

#### Scenario: 前回の振り返りだけの回
- **WHEN** これまでの配信の要約がある状態で、相方が前回の内容を説明しただけの記録を要約する
- **THEN** 要約の指示に、これまでの配信の要約が「すでに与えている情報」として添えられ、振り返りを今回の出来事として残さないよう指示される

### Requirement: 配信をまたいで要約を積み上げる
システムは、終了するとき、今回の要約が「（なし）」でなければ、累積の要約、まだまとめ直していない前回の要約、今回の要約を、要約のモデルで 1 つの累積の要約にまとめ直さなければならない（SHALL）。累積の要約は設定した文字数（既定 20,000 文字）以内とし、古い配信ほど要点に縮め、動作確認のやり取りと、ペルソナに書いてあることは残さないよう指示しなければならない（SHALL）。渡した要約に書かれていない出来事を作らず、新しい出来事のない回には見出しを立てないよう指示しなければならない（SHALL）。まとめ直しに失敗するか 60 秒以内に終わらない場合は、累積の要約を変えず、今回の要約をまとめ直していないものとして保存しなければならない（SHALL）。今回の要約は、日時を付けて履歴のファイルにも残さなければならない（SHALL）。

#### Scenario: 配信を終える
- **WHEN** 累積の要約がある状態で、今回の要約「- ニブルヘイムを進めた」を持って終了する
- **THEN** 累積の要約と今回の要約から、20,000 文字以内の新しい累積の要約が作られて保存され、今回の要約が履歴のファイルに残る

#### Scenario: まとめ直しに失敗する
- **WHEN** 終了時のまとめ直しが失敗する
- **THEN** 累積の要約は変わらず、今回の要約がまとめ直していないものとして保存され、次の起動時に指示に入る

#### Scenario: 前回まとめ直せなかった要約がある
- **WHEN** まとめ直していない前回の要約がある状態で起動し、今回の配信を終える
- **THEN** 累積の要約、前回の要約、今回の要約の 3 つから、新しい累積の要約が作られる

#### Scenario: 書かれていない出来事を作らない
- **WHEN** まとめ直しを求める
- **THEN** 指示に、渡した要約に書かれていない出来事を作らないことと、新しい出来事のない回には見出しを立てないことが含まれる
