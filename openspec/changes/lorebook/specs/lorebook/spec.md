# Spec Delta

## Purpose

配信者が明示的に覚えておくよう頼んだことを、要約とは別に控えておき、話題にキーワードが出たときだけ答える役への指示に入れる。

## ADDED Requirements

### Requirement: 要約と控えの役割を分ける
要約は配信の流れと出来事だけを持ち、言葉（人物・視聴者・場所・アイテム・用語など）の詳しい情報は控えの項目が持たなければならない（SHALL）。システムは、要約を作るとき、要約と一緒に言葉ごとの控えの項目（キーワードと内容）を返させ、項目を作るか更新しなければならない（SHALL）。キーワードには、その言葉の表記ゆれ・読み・聞き間違いのパターンと、視聴者ならチャットの投稿者名を入れさせ、毎回のように出てくる言葉（「マスター」「配信者」「相方」、相方の名前など）は使わせてはならない（MUST NOT）。要約する記録にキーワードが出てくる既存の項目は、その内容を要約のモデルに見せ、更新した全文を返させなければならない（SHALL）。返った項目のキーワードが既存の項目と重なれば、その項目の内容を置き換え、キーワードを足さなければならない（SHALL）。新しく分かったことのない言葉の項目は返させてはならない（MUST NOT）。

#### Scenario: 要約で視聴者の控えができる
- **WHEN** 要約の返事に、キーワード「@AtelierDokan」「ドカン」の項目「攻略情報に詳しい常連」が含まれる
- **THEN** その項目が作られて保存され、要約にはその人の詳しい情報が入らない

#### Scenario: 既存の控えを更新する
- **WHEN** 項目「ドカン」がある状態で、記録に「ドカン」が出てくる要約を作り、返事に同じキーワードの更新された項目が含まれる
- **THEN** 要約の指示に既存の項目の内容が添えられ、項目の内容が更新後の全文に置き換わる

### Requirement: 返事の合図で控えを作る
システムは、答える役の返事に `【記憶: キーワード=<キーワードを「、」か「,」で区切ったもの> ／ 内容=<内容>】` が含まれていたら、そのキーワードと内容で項目を作り、作った日時とともにファイルに保存しなければならない（SHALL）。合図は読み上げに回してはならない（MUST NOT）。1 つの返事に複数の合図があれば、それぞれ項目にしなければならない（SHALL）。形式に合わない合図は、項目にせず警告を記録し、読み上げからは取り除かなければならない（SHALL）。

#### Scenario: 覚えておくよう頼まれる
- **WHEN** 返事が「承知しました、覚えておきます。【記憶: キーワード=ごつミノ、ゴツミノ ／ 内容=ごつミノは一般モンスター、通常ミノがボス属性】」である
- **THEN** キーワード「ごつミノ」「ゴツミノ」と内容の項目が保存され、「承知しました、覚えておきます。」だけが読み上げに回される

#### Scenario: 形式に合わない合図
- **WHEN** 返事に「【記憶: ごつミノは一般モンスター】」が含まれる
- **THEN** 項目は作られず警告が記録され、合図は読み上げられない

### Requirement: 返事の合図で控えを消す
システムは、答える役の返事に `【忘却: <キーワード>】` が含まれていたら、そのキーワードを持つ項目をすべて消し、ファイルに保存しなければならない（SHALL）。合図は読み上げに回してはならない（MUST NOT）。

#### Scenario: 忘れるよう頼まれる
- **WHEN** 「ごつミノ」をキーワードに持つ項目がある状態で、返事に「【忘却: ごつミノ】」が含まれる
- **THEN** その項目が消えて保存され、合図は読み上げられない

### Requirement: キーワードが出たら控えを指示に入れる
システムは、答える役に問い合わせるたびに、要約以降の記録の最後の設定件数（既定 6 件）の発言の本文（チャットは投稿者名を含む）から、各項目のキーワードを探さなければならない（SHALL）。話者の区別（「配信者」「相方」「チャット」）は探す対象に含めてはならない（MUST NOT）。照合では、ひらがなとカタカナ、英字の大文字と小文字を区別してはならない（MUST NOT）。当たった項目の内容を、指示の最後に「控え」として入れなければならない（SHALL）。当たらない項目を入れてはならない（MUST NOT）。

#### Scenario: キーワードが出る
- **WHEN** 項目「ごつミノ」があり、直近の記録に「配信者: ゴツミノ強くない?」がある
- **THEN** その項目の内容が指示に入る

#### Scenario: 話者の区別では当たらない
- **WHEN** 項目「配信者」があり、直近の記録が「配信者: こんにちは」だけである
- **THEN** 指示にその項目は入らない

#### Scenario: キーワードが出ない
- **WHEN** 項目「ごつミノ」があり、直近の記録にそのキーワードがない
- **THEN** 指示にその項目は入らない

### Requirement: 当たった控えはしばらく入れたままにする
システムは、キーワードが当たった項目を、その後の設定回数（既定 3 回）の問い合わせでも、キーワードが出ていなくても指示に入れなければならない（SHALL）。退去したら、入れたままにしている項目をすべて外さなければならない（SHALL）。

#### Scenario: 話題が続く
- **WHEN** 項目「ごつミノ」が当たった後、キーワードの出ない問い合わせが 3 回続き、さらにもう 1 回続く
- **THEN** 3 回目までは項目が指示に入り、4 回目には入らない

#### Scenario: 退去する
- **WHEN** 項目が入れたままになっている状態で退去し、再び召喚される
- **THEN** キーワードが出るまで、その項目は指示に入らない

### Requirement: 入れる量の上限
システムは、1 回の問い合わせに入れる控えの内容の合計を、設定した文字数（既定 3,000 文字）以内にしなければならない（SHALL）。超える場合は、最近キーワードが当たった項目を優先し、入らなかった項目があったことを記録しなければならない（SHALL）。

#### Scenario: 上限を超える
- **WHEN** 当たった項目の内容の合計が 3,000 文字を超える
- **THEN** 最近当たったものから 3,000 文字以内で入り、入らなかった項目があったことが記録される

### Requirement: 控えの操作を記録する
システムは、項目を作ったとき、消したとき、問い合わせに入れたときに、そのキーワードをログに記録しなければならない（SHALL）。

#### Scenario: 控えを作る
- **WHEN** 合図から項目が作られる
- **THEN** 作った項目のキーワードと内容がログに記録される
