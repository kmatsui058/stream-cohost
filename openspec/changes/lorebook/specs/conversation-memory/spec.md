# Spec Delta

## MODIFIED Requirements

### Requirement: 要約の作り方
システムは、要約を設定したモデル（既定 `gemini-3.8-flash`）で、設定した文字数（既定 4,000 文字）以内の日本語で作るよう求めなければならない（SHALL）。残すもの（配信で今やっていることと流れ、読み上げられた物語やセリフの要点、配信者が話した事実・好み・予定・感想、配信者や視聴者が教えてくれたことや訂正されたこと、相方とのやり取りで答えた内容）と捨てるもの（相づち、挨拶の繰り返し、言い淀み、相方の仕組みの動作確認・設定・不具合のやり取り）を指示しなければならない（SHALL）。人物（視聴者を含む）・場所・アイテム・用語などの言葉の詳しい情報は、要約には名前だけを書き、詳細は控え（lorebook）の項目として、要約と同じ返事の中で別に返すよう指示しなければならない（SHALL）。ペルソナ、今日の配信の情報、これまでの配信の要約を「すでに与えている情報」として添え、そこに書いてあること（配信者や相方の名前・設定、過去の配信の出来事など）を繰り返さないよう指示しなければならない（SHALL）。相方や配信者が過去の配信を振り返って話しただけの内容は、今回の出来事として残さないよう指示しなければならない（SHALL）。残すものがなければ「（なし）」とだけ返すよう指示しなければならない（SHALL）。要約が空で返った場合は失敗として扱い、記録と前回の要約を変えてはならない（MUST NOT）。

#### Scenario: 要約を求める
- **WHEN** 要約を作る
- **THEN** 設定したモデルに、4,000 文字以内であることと、残すもの・捨てるもの（動作確認のやり取りを含む）と、何もなければ「（なし）」とする指示が送られる

#### Scenario: すでに与えている情報は繰り返さない
- **WHEN** ペルソナに配信者の名前が書かれた状態で要約を作る
- **THEN** 要約の指示に、ペルソナと今日の配信の情報が「すでに与えている情報」として添えられ、そこに書いてあることを繰り返さないよう指示される

#### Scenario: 言葉の詳細は控えに分ける
- **WHEN** 記録に、視聴者「@AtelierDokan」が攻略情報をくれたことと、その人の特徴が含まれる状態で要約を作る
- **THEN** 要約の指示に、要約には名前だけを書き、その人の詳しい情報は控えの項目として返すことが含まれる

#### Scenario: 要約が空で返った
- **WHEN** 要約を求めた結果が空文字だった
- **THEN** 要約は失敗として扱われ、記録と前回の要約はそのまま残る

#### Scenario: 前回の振り返りだけの回
- **WHEN** これまでの配信の要約がある状態で、相方が前回の内容を説明しただけの記録を要約する
- **THEN** 要約の指示に、これまでの配信の要約が「すでに与えている情報」として添えられ、振り返りを今回の出来事として残さないよう指示される

### Requirement: 配信をまたいで要約を積み上げる
システムは、終了するとき、今回の要約が「（なし）」でなければ、累積の要約、まだまとめ直していない前回の要約、今回の要約を、要約のモデルで 1 つの累積の要約にまとめ直さなければならない（SHALL）。累積の要約は設定した文字数（既定 20,000 文字）以内とし、古い配信ほど要点に縮め、動作確認のやり取りと、ペルソナに書いてあることと、言葉の詳しい情報（控えにあるもの）は残さないよう指示しなければならない（SHALL）。渡した要約に書かれていない出来事を作らず、新しい出来事のない回には見出しを立てないよう指示しなければならない（SHALL）。まとめ直しに失敗するか設定した時間（既定 120 秒）以内に終わらない場合は、累積の要約を変えず、今回の要約をまとめ直していないものとして保存しなければならない（SHALL）。今回の要約は、日時を付けて履歴のファイルにも残さなければならない（SHALL）。

#### Scenario: 配信を終える
- **WHEN** 累積の要約がある状態で、今回の要約「- ニブルヘイムを進めた」を持って終了する
- **THEN** 累積の要約と今回の要約から、20,000 文字以内の新しい累積の要約が作られて保存され、今回の要約が履歴のファイルに残る

#### Scenario: まとめ直しに失敗する
- **WHEN** 終了時のまとめ直しが失敗する
- **THEN** 累積の要約は変わらず、今回の要約がまとめ直していないものとして保存され、次の起動時に指示に入る

#### Scenario: 前回まとめ直せなかった要約がある
- **WHEN** まとめ直していない前回の要約がある状態で起動し、今回の配信を終える
- **THEN** 累積の要約、前回の要約、今回の要約の 3 つから、新しい累積の要約が作られる

#### Scenario: 書かれていない出来事を作らない
- **WHEN** まとめ直しを求める
- **THEN** 指示に、渡した要約に書かれていない出来事を作らないことと、新しい出来事のない回には見出しを立てないことが含まれる

### Requirement: 記憶を保存する
システムは、要約を更新するたびと、終了するときに、累積の要約、今回の要約、今回の直近の発言を、保存日時とともにファイルへ保存しなければならない（SHALL）。配信中の保存では、累積の要約を変えてはならない（MUST NOT）。終了するときは、保存の前に今回の要約の更新を試みなければならない（SHALL）。要約の更新に失敗するか設定した時間（既定 120 秒）以内に終わらない場合も、その時点の内容を保存しなければならない（SHALL）。今回の要約が「（なし）」のときは、今回の要約と直近の発言を保存せず、前回のものを残さなければならない（SHALL）。

#### Scenario: 終了する
- **WHEN** 記録がある状態で終了する
- **THEN** 要約が更新されてから、要約と直近の発言が保存される

#### Scenario: 終了時に要約が失敗する
- **WHEN** 終了時の要約の更新が失敗する
- **THEN** それまでの要約と発言がそのまま保存される

#### Scenario: 配信中に要約を更新する
- **WHEN** 累積の要約を読み込んだ状態で、配信中に要約が更新される
- **THEN** 累積の要約は変わらず、今回の要約と直近の発言が保存される

#### Scenario: 動作確認だけのセッションを終える
- **WHEN** 今回の要約が「（なし）」の状態で終了する
- **THEN** 累積の要約、前回の要約と直近の発言は、そのまま残る

## ADDED Requirements

### Requirement: 要約に時間の上限を設ける
システムは、配信中の要約が設定した時間（既定 120 秒）以内に終わらない場合、その要約を失敗として扱い、記録と前回の要約を変えずに、次の機会にやり直せるようにしなければならない（SHALL）。

#### Scenario: 配信中の要約が返ってこない
- **WHEN** 配信中の要約が 120 秒以内に返ってこない
- **THEN** 失敗として扱われ、記録は残り、次に記録がたまったときに再び要約が作られる
