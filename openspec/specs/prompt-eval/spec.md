# prompt-eval Specification

## Purpose
persona を変更したときに、同じ入力に対して相方がどう返事をするかを版ごとに並べて比べ、変更の効果を配信の前に確かめられるようにする。

## Requirements

### Requirement: 評価ケースを版ごとに実行する
システムは、評価ケースのそれぞれについて、今の persona と比較用の persona の両方で、同じ入力を AI に与えて返事を受け取らなければならない（SHALL）。比較用の persona は git の版で指定でき、指定がなければ既定の版を使わなければならない（SHALL）。あるケースで返事を受け取れなかった場合は、そのケースを失敗として記録し、残りのケースを続けなければならない（SHALL）。

#### Scenario: 2 つの版で実行する
- **WHEN** 15 個の評価ケースで評価を実行する
- **THEN** 各ケースについて、今の persona と比較用の persona の返事が 1 つずつ得られる

#### Scenario: 返事が返ってこない
- **WHEN** あるケースで、制限時間内に返事が返ってこない
- **THEN** そのケースは失敗として記録され、次のケースに進む

### Requirement: 返事をルールでチェックする
システムは、返事ごとに次の項目をチェックしなければならない（SHALL）。70 文字を超える長さ、疑問で終わるか、「ですね」の有無、サポート口調の言い回し、共感の定型句、自分の役割への言及、配信者を「オコハ」以外の名前で呼んでいないか。

#### Scenario: サポート口調の返事
- **WHEN** 返事が「了解しました。準備はよろしいですか。」である
- **THEN** サポート口調と、疑問で終わることが記録される

#### Scenario: 誤った呼び方
- **WHEN** 返事に「小波さん」が含まれる
- **THEN** 呼び方の誤りが記録される

### Requirement: 結果を書き出す
システムは、ケースごとに入力と両方の版の返事とチェック結果を並べた表と、版ごとのチェックの集計を、Markdown のファイルに書き出さなければならない（SHALL）。

#### Scenario: 評価が終わる
- **WHEN** 全ケースの実行が終わる
- **THEN** `eval/results/` に、ケースごとの比較表と、版ごとの集計が書かれたファイルができる

### Requirement: 黙る／話すの正解と照合する
システムは、評価ケースに「黙るべき」か「話すべき」かの正解が書かれている場合、返事が黙る合図だけかどうかを判定し、正解と合っているかを記録しなければならない（SHALL）。条件ごとに、正解と合ったケースの数を集計しなければならない（SHALL）。

#### Scenario: 黙るべき場面で黙った
- **WHEN** 正解が「黙るべき」のケースで、返事が「スルー。」である
- **THEN** 正解と合っていると記録される

#### Scenario: 話すべき場面で黙った
- **WHEN** 正解が「話すべき」のケースで、返事が「スルー」である
- **THEN** 正解と合っていないと記録される

### Requirement: 条件にツールを指定する
システムは、評価の条件ごとに、AI に使わせるツール（Google 検索）を指定できなければならない（SHALL）。指定がない条件では、ツールを使わせてはならない（MUST NOT）。

#### Scenario: 検索ありの条件
- **WHEN** 条件に Google 検索を指定して評価を実行する
- **THEN** その条件のセッションでは、AI が Google 検索を使える

### Requirement: 検索したかを記録する
システムは、返事ごとに、AI が検索などのツールを実際に使ったかどうかを記録し、条件ごとに使った回数を集計しなければならない（SHALL）。

#### Scenario: 検索して答えた
- **WHEN** AI が検索の結果を使って返事をする
- **THEN** その返事は「検索した」と記録される

### Requirement: 評価ケースのファイルを指定する
システムは、評価に使うケースのファイルを指定できなければならない（SHALL）。指定がなければ既定のケースを使わなければならない（SHALL）。

#### Scenario: 検索向けのケースで実行する
- **WHEN** 検索向けのケースのファイルを指定して実行する
- **THEN** そのファイルのケースで評価が行われる

### Requirement: 直前のやり取りを入力に含める
システムは、評価ケースに直前のやり取りが書かれている場合、本番と同じ「話者: 発言」の形で、相方への指示に「直前のやり取り」として入れなければならない（SHALL）。

#### Scenario: 文脈を問うケース
- **WHEN** 直前に読み上げた NPC のセリフを含むケースを実行する
- **THEN** そのセリフが「直前のやり取り」として指示に入った状態で、質問が与えられる

### Requirement: テキストのモデルで評価する
システムは、評価の条件で通常の生成 API が指定された場合、Live の接続を使わずに、同じ指示（persona、今日の配信、直前のやり取り）と同じ入力で、テキストの返事を受け取らなければならない（SHALL）。条件に考える量やツールが指定されていれば、それを生成の設定に含めなければならない（SHALL）。返事に検索の根拠情報が含まれる場合は、ツールを使った痕跡として記録しなければならない（SHALL）。

#### Scenario: テキストのモデルで返事を受け取る
- **WHEN** 条件に通常の生成 API と `gemini-3.8-flash` が指定されている
- **THEN** 指示と入力を渡して生成が 1 回呼ばれ、返事の文章と、返事が終わるまでの時間が記録される

#### Scenario: 考える量と検索を指定する
- **WHEN** 条件に考える量 HIGH と Google 検索が指定され、返事に検索の根拠情報が含まれる
- **THEN** 生成の設定に考える量と検索が含まれ、ツールを使った痕跡が記録される
