# 手動スモークテスト

自動テストでは外部サービスを偽物に差し替えているので、実機・実 API との結合はこの手順で確認する。配信は始めずに、ヘッドホンをつけて行う。

## 前提

- `.env` に `GEMINI_API_KEY`、`MIC_DEVICE`、`OBS_WS_PASSWORD` が入っている
- VOICEVOX アプリと OBS が起動していて、OBS の WebSocket サーバーが有効になっている
- OBS に、URL が `http://127.0.0.1:8787/` のブラウザソースがあり、「OBS で音声を制御する」が有効、モニタリングが「モニターと出力」になっている

## 手順

| # | 操作 | 期待する結果 | 確認する仕様 |
|---|---|---|---|
| 1 | `npm start` | ログに `VOICEVOX ENGINE`、`接続完了`、`ffmpeg 起動`、`OBS に接続` が出る | operator-controls、live-session、audio-input、screen-capture |
| 2 | OBS のブラウザソースを表示する | 左下に「SOUND ONLY」と表示名が暗い状態で出て、左上に `cohost: 未接続` が出ない。ブラウザソースをつなぐ前は、自発発話が起きない（ログに `控えます`） | stream-overlay、turn-taking |
| 3 | マイクに話しかける | ナースロボ＿タイプＴの声で返事が来て、字幕が出て、SOUND ONLY 表示が明るくなる。話し終わると暗く戻る | turn-taking、speech-output、stream-overlay |
| 4 | 画面について聞く（例：「今の画面どう？」） | 映っているものに触れた返事が来る | screen-capture |
| 5 | 相方が喋っている途中で話しかける | 相方が黙る（ログに `発話を中断`） | turn-taking |
| 6 | 30〜45 秒黙る | ログに `【合図】` の注入が出て、相方から話しかけてくる | turn-taking |
| 7 | コンソールで `r` | ログに `ローテーション開始`、`要約を更新`、`接続中 … 方式=新規` が出て、会話が続く | live-session、conversation-memory |
| 8 | コンソールで `m` | 要約と直近の発言が表示される | operator-controls |
| 9 | 配信中に `v <動画ID>` | ログに `チャット取得開始`、コメントが来ると `💬` が出て、相方が名前を呼んで反応する | live-chat |
| 10 | コンソールで `q` | ログに `終了します` が出て、プロセスが終わる | operator-controls |

## 実施記録

### 2026-10-18（初回）

- 実施した手順：1〜6
- 結果：手順 3〜6 はすべて期待どおり。割り込みでの停止はログ上 2 回とも正しく動いた。コンテキストは 10 分で約 6,000 トークン。
- 未実施：7〜10（手順 7 は、約 10 分ごとのサーバーからの切断予告による張り直しも含めて、次回確認する）
- 見つかった問題
  - ブラウザソースをつなぐ前から、沈黙時の自発発話が約 40 秒おきに走り、誰にも聞こえない発言を 14 回していた → 変更 `quiet-without-overlay` で対応
  - 口調が丁寧なアシスタント調（「承知いたしました」など）で、相方らしくない → 配信者が persona.md を書き直す
