# stream-cohost — 配信用 AI 相方

[![CI](https://github.com/kmatsui058/stream-cohost/actions/workflows/ci.yml/badge.svg)](https://github.com/kmatsui058/stream-cohost/actions/workflows/ci.yml)

配信者に名前を呼ばれると現れて質問に答え、会話が終わったら消える AI 相方。相方は配信者の人工精霊「オルダ・ヴァール」（声：VOICEVOX ナースロボ＿タイプＴ）。

マイク音声は Gemini Live の文字起こし専用モデルで常に文字にしておき、「オルダ」「ヴァール」と呼ばれたら召喚する。召喚中は、発話のたびに、考えてから答えるモデル（Gemini 4 Argon）へ「要約＋要約以降の記録＋直近の配信画面」を送って返事をもらい、VOICEVOX で読み上げる。OBS のブラウザソースには、召喚中だけ立ち絵（喋ると表情が変わり、明るくなる）と字幕を出す。YouTube のライブチャットも読む。

 │                                                            │                （gemini-4-argon）
 │                                                            │ 1文ずつ            │
 │                                                            ▼                    │

外部に出るデータは **Gemini（マイク音声・召喚中の配信画面・記録とチャット本文）** と **YouTube Data API（チャット取得のみ）** の 2 つだけ。VOICEVOX はローカルで動く。

### なぜこの構成か

| 判断 | 理由 |
|---|---|
| **聞く役と答える役を分ける** | 2026-10-21 までは gemini-3.8-live に聞かせて答えさせていたが、呼ばれていない独り言に答える・不確かなことを断定する・相手の言葉を言い直すだけ、が目立った。同じ場面の評価（`eval/cases-1021.json`）では、考えてから答える Argon のほうが答えの中身がよかった。Argon は Live API に対応していないので、聞くのは Live、答えるのは通常の生成 API にした。返事まで 5〜6 秒かかる。 |
| 聞く役は文字起こし専用モデル | 返事を生成しないので安い（約 $0.009/分）。日本語に固定でき、「オルダ」などを聞き取りやすい語として登録できる。無音（`VAD_SILENCE_MS`）で発話を区切ってくれる。 |
| 名前で召喚し、相方が自分で退去する | 「答えるか」の判定に AI を使わず、名前の文字列照合だけで済む。召喚中は名前なしで追い質問ができ、会話が終わったら相方が返事に `【退去】` を付けて消える。待機中は答える役を呼ばないので費用がかからない。 |
| 画面は obs-websocket のスクリーンショット | 配信に出ている画面（プログラムシーン）を、そのまま「視聴者と同じもの」として渡せる。仮想カメラや画面キャプチャを別に用意しなくていい。直近の数枚だけを持っておき、問い合わせに添える。 |
| マイクは ffmpeg | Node からマイクを読むネイティブモジュールはビルドが面倒。ffmpeg に生 PCM を出させて stdout で受けるのが一番トラブルが少ない。 |
| 再生は OBS のブラウザソース | 音を OBS のミキサーに直接入れられるので、仮想オーディオケーブルが要らない。表示と字幕も同じページで出せる。 |

## 3. 召喚から退去まで

1. マイク音声は **常時** 聞く役（Live の文字起こし専用モデル）に流している（100ms 単位）。無音が `VAD_SILENCE_MS`（既定 800ms）続くと 1 発話として区切られ、確定した文字起こしが届く（ログとコンソールに `🎤`。話している途中の文字起こしは `LOG_DEBUG=1` で `🎤…`）。
2. 発話とチャットは、待機中も記録する（要約の材料になる）。
3. **召喚**：発話かチャットに召喚の言葉（`SUMMON_WORDS`、既定「オルダ」「ヴァール」。ひらがなでも可）が入っていたら、相方が現れる（ログに `召喚されました`、画面に立ち絵）。
4. **会話**：召喚中は、発話・チャットが届くたびに、答える役（`gemini-4-argon`）に問い合わせる。送るのは次の 3 つ。
   - 指示：persona.md ＋ 今日の配信 ＋ 前回の配信の要約 ＋ ここまでの要約
   - 要約以降の記録すべて（「配信者: 」「相方: 」「チャット: 名前: 本文」）
   - 直近の配信画面 3 枚（`RESPONDER_FRAMES`。画面がまだなければ「見えていない」と書き添える）
5. 問い合わせは同時に 1 つ。返事を待っている間に話した分は記録に積み、返事の後にもう 1 回だけまとめて問い合わせる。
6. 返事は `。！？!?♪` と改行で文に区切って、1 文ずつ VOICEVOX で合成して読み上げる（ログに `💬`）。`スルー` だけなら読み上げない（ログに `（黙ると判断）`）。
7. **退去**：相方が会話は終わったと判断すると、返事の最後に `【退去】` を付ける。読み上げが終わったら立ち絵が消え、待機に戻る（ログに `退去しました`）。自動で退去する安全策はないので、居座るときは `o` で退去させる。

**割り込み（バージイン）**：相方が喋っている間に配信者が話したときの動作は `BARGE_IN` で選ぶ。既定の `duck` は、話している途中（聞く役の途中経過の文字起こし）で相方の声を `DUCK_VOLUME`（既定 0.3）まで下げ、話し終える（発話が確定するか、途中経過が `DUCK_RELEASE_MS`＝既定 1 秒届かない）と元に戻す。`stop` は発話が確定した時点で中断する（以前の動き）。`off` は何もしない。

**チャット**：届いたら記録する。名前が入っていれば召喚し、召喚中なら問い合わせる。

**対象の配信の決め方**：OBS の配信設定で配信枠を選んでおけば、その動画 ID（`broadcast_id`）を読み取って、チャットの読み取り先と配信情報を自動でその配信に合わせる。読み取るのは、OBS につながったとき・配信の開始停止のとき・15 秒おき（PC 内の OBS への問い合わせなので YouTube API は消費しない）。`.env` の `YOUTUBE_VIDEO_ID` や `v <動画ID>` でも指定でき、最後に起きた指定が使われる。

**配信のタイトルと概要欄**：チャットの読み取りを始めるときに、同じ API 呼び出しで配信のタイトルと概要欄も受け取り、次の問い合わせから指示に「今日の配信」として入れる（概要欄は 1,000 文字まで）。persona.md は特定のゲームに依存しない書き方にしてあるので、何のゲームか・今日は何をするかは、配信のタイトルと概要欄に書いておく。

### 記憶

- 要約していない記録が 12,000 字（`SUMMARIZE_AT_CHARS`）を超えたら、直近 12 件（`RECENT_ENTRIES`）を残して、それより前を `gemini-3.8-flash`（`SUMMARY_MODEL`）で要約に畳み込む（4,000 字以内、`SUMMARY_MAX_CHARS`）。読み上げた物語の要点、訂正されたこと、相方が答えた内容なども残すよう指示している。
- 相方が今何を覚えているかは `logs/summary.txt`、またはコンソールで `m` を入力すると見られる。
- **配信をまたいだ引き継ぎ**：終了するとき（`q` / Ctrl+C）に、今回分を最後まで要約し、「これまでの配信の要約（累積）」と 1 つにまとめ直して `logs/carryover.json` に保存する（20,000 字以内、`LONG_SUMMARY_MAX_CHARS`。古い配信ほど要点に縮める）。次に起動したときに「これまでの配信の要約」として指示に入る。各回の要約は `logs/sessions/` に 1 ファイルずつ残る。配信中の保存では累積の要約を上書きしないので、途中で落ちても前回までの記憶は消えない（まとめ直しは次回の終了時に行う）。テストなどで引き継ぎたくないときは `npm run start:fresh` で起動する。
- **要約に残さないもの**：相方の動作確認・設定・不具合のやり取りと、persona.md や配信のタイトルにすでに書いてあること（配信者や相方の名前など）。動作確認だけの回は要約が「（なし）」になり、引き継ぎの記憶は何も変わらない。

### 聞く役のセッションの寿命

- Live API の **1 本の接続は約 10 分で切れる**。切れる前にサーバーから `goAway` が届くので、そこで新しいセッションに乗り換える。文字起こしだけなので、文脈の引き継ぎは要らない。
- 予期しない切断のときは 1→2→4…最大 30 秒の間隔で再接続する。ログには `[listener] 切断 code=... reason=...` が出る。

## 4. セットアップ

### 4.1 インストール済みのもの

- Node.js 22（既存）
- ffmpeg 9.0（`winget install Gyan.FFmpeg.Essentials`）※ **PATH が通るのは、新しく開いたターミナルから**。VS Code ごと再起動するのが確実。
- VOICEVOX 0.25.2（`winget install HiroshibaKazuyuki.VOICEVOX`）。DirectML 版なので Radeon でも GPU で合成できる。`npm start` で VOICEVOX アプリも一緒に起動する（アプリが ENGINE を `:50021` で立てる。すでに起動していれば二重には起動しない）。立ち上がる前に接続を確認するので、起動直後に「VOICEVOX に接続できません」が出ることがあるが、立ち上がれば読み上げは動く。
- npm パッケージ：`@google/genai`、`obs-websocket-js`、`ws`

### 4.2 音声の経路（前提）

- OBS のデスクトップ音声は **オフ**。AG03MK2 の TO PC スイッチは **INPUT MIX**（PC の再生音はマイク側に戻らない）。
- そのため、配信に乗るのは「マイク」と「OBS に明示的に追加したソース」だけ。相方の声は、ブラウザソースの「OBS で音声を制御する」経由で乗る。**このチェックを外すと、相方の声は配信に乗らない**。
- Gemini に届く音声もマイクだけ。ただしスピーカーで聞いている場合は、空気越しに相方の声が入る。

### 4.3 やってもらうこと

1. **Gemini API キー**：<https://aistudio.google.com/apikey> で発行する。
   - ⚠ 無料枠では、送ったデータが Google のプロダクト改善に使われる。配信画面とマイク音声が対象になるので、気になるなら課金を有効にして有料枠で使う。
2. **OBS の WebSocket を有効化**：OBS の「ツール → WebSocket サーバー設定」で「WebSocket サーバーを有効にする」にチェックを入れる。パスワードは「接続情報を表示」で確認する。（今は無効になっている）
3. **`.env` を作る**：`.env.example` をコピーして `GEMINI_API_KEY`、`MIC_DEVICE`、`OBS_WS_PASSWORD` を埋める。
   - マイク名は `npm run mics` で確認できる。今の環境で見えるのは `Line (2- Yamaha AG03MK2)` だけ。
4. **OBS にブラウザソースを追加**（相方を出したいシーンに）：
   - URL `http://127.0.0.1:8787/`、幅 1920、高さ 1080
   - ✅「OBS で音声を制御する」にチェック → 音声ミキサーに出てくるので、その「オーディオの詳細プロパティ」で、モニタリングを「モニターと出力」にする（自分のヘッドホンでも聞こえるように）
   - カスタム CSS は空にする（ページ側で背景を透明にしている）
5. **表示（立ち絵）**：画面左下に、相方の立ち絵をバストアップで小さく出す。喋っていない間は `default.png` の表情で暗く（明るさ 35%）、喋っている間は `smile.png` に切り替わり、再生音量に合わせて明るくなる。
   - 立ち絵は `.env` の `CHARACTER_DIR` に、`default.png` と `smile.png` が入ったフォルダを指定する。今は H1N4「立ち絵素材No.1【白髪幸薄系少女】」私服版の `no01_casual_cardigan_off_png` を使っている。
   - **素材は再配布が禁止されているので、リポジトリには入れない**（立ち絵が写ったスクリーンショットもコミットしない）。
   - `CHARACTER_DIR` が空、または 2 枚がそろっていないときは、代わりに「SOUND ONLY」を出す。
   - 表示名（`COHOST_DISPLAY_NAME`、既定 `ORÐA-VÁR`）は立ち絵の下端に出る。切り取り位置や大きさは `public/overlay.css` の `--portrait-*` で調整する。
   - ナースロボ＿タイプＴの公式立ち絵は、規約で「他のキャラクターとして扱うこと」が禁止されているため使っていない。
6. **（任意）YouTube チャット**：Google Cloud Console で YouTube Data API v3 を有効にし、API キーを `YOUTUBE_API_KEY` に入れる。動画 ID は配信ごとに変わるので、`.env` に書くか、起動後に `v <動画ID>` で指定する。
7. **声とクレジット**：声の既定はナースロボ＿タイプＴ ノーマル（ID 47）。配信の概要欄に「VOICEVOX:ナースロボ＿タイプＴ」と「立ち絵：H1N4」を書く（立ち絵のクレジットは「可能であれば」とされている）。声を変えるときは、`npm run speakers` で ID の一覧を出して `VOICEVOX_SPEAKER` に指定する（各キャラの利用規約に従う）。
8. **キャラクター**：相方の設定と話し方は `persona.md`。変更したら再起動する。

### 4.4 起動

```powershell
cd ~\stream-cohost
npm start              # 前回の記憶を引き継いで起動
npm run start:fresh    # 引き継がずに起動（テスト用）
```

起動するとコンソールに操作の一覧が出る。OBS のブラウザソースの左上に赤字で `cohost: 未接続` が出ていなければ、画面とつながっている。

## 5. 配信中の操作（起動したコンソールに入力して Enter）

| 入力 | 動作 |
|---|---|
| `p` | **一時停止／再開**。マイクを送らず、問い合わせもしない。発話も止める。席を外すときや、見せられない画面を出すときに使う |
| `s` | 今の発話をスキップする（キューも空にする） |
| `t オルダ、こんにちは` | テキストで話しかける（マイクの代わり。発話と同じ扱い） |
| `o` | 召喚／退去を切り替える（居座るときや、手で呼びたいとき） |
| `v <動画ID>` | チャットを読む配信を切り替える |
| `r` | 今すぐ要約する |
| `m` | 今の要約と、要約以降の記録を表示する |
| `q` / Ctrl+C | 終了 |

**最速の緊急停止**：OBS で相方のブラウザソースを非表示にするか、ミキサーでミュートする（プロセスは動いたままで、配信には出なくなる）。そのあと `p` を押す。

## 6. トラブルシューティング

まず `logs/` の当日ファイルを見る。タグ（`[listener]` `[director]` `[responder]` `[mic]` など）で、どの部品の問題か分かる。

| 症状 | 確認すること | 対処 |
|---|---|---|
| 起動直後に `VOICEVOX に接続できません` | VOICEVOX アプリは起動しているか | アプリを起動する。`curl http://127.0.0.1:50021/version` で確認できる |
| `[mic] ffmpeg を起動できません` | 新しいターミナルで `ffmpeg -version` が通るか | ターミナルや VS Code を再起動する。それでも駄目なら `FFMPEG_PATH` にフルパスを書く |
| `[mic] ... Could not find audio device` | `npm run mics` の名前と `MIC_DEVICE` が完全に一致しているか | 名前をコピーし直す。USB を挿し直すと名前の番号（`2-` など）が変わることがある |
| 呼んでも現れない | `LOG_DEBUG=1` で `🎤` が出るか。出ているなら、名前がどう書き起こされているか | 🎤 が出なければマイクか聞く役の問題（入力レベル、デバイス名、`[listener]` のログ）。名前が別の字になっているなら `SUMMON_WORDS` に足す |
| 現れるが何も言わない | `[director] 問い合わせに失敗` が出ていないか | エラーの内容を見る。`RESPONDER_MODEL` と API キー、クレジットの残高（`prepayment credits are depleted`）を確認する |
| 消えない（居座る） | — | `o` で退去させる。頻繁なら persona.md の「召喚と退去」を見直す |
| `[listener] 切断 code=1008` | モデル名と API キー | 1008 は「このキーではそのモデルを使えない／設定が不正」。`LISTENER_MODEL` を確認する |
| `[listener] 切断` が延々続く | reason の内容 | 再起動する |
| ログに 🔊 は出るのに音が出ない | 「オーバーレイ未接続」の警告が出ていないか | OBS のブラウザソースのプロパティで「現在のページを再読み込み」。音が出ないならミキサーとモニタリングの設定を確認する |
| 画面左上に赤字で `cohost: 未接続` | `npm start` が動いているか | サーバーを起動すれば 2 秒以内に自動で再接続する |
| 相方の声が小さくなったまま戻らない／すぐ戻る | `DUCK_RELEASE_MS` | 戻るのが早すぎるなら伸ばす。下げたくなければ `BARGE_IN=off`、止めたいなら `BARGE_IN=stop` |
| 相方が自分の声に反応し続ける／延々しゃべる | ① AG03MK2 の TO PC スイッチが **INPUT MIX** か（標準の設定。LOOPBACK だと PC の音がマイクに混ざる）② スピーカーで聞いていないか（マイクが空気越しに拾う） | ① INPUT MIX に戻す ② ヘッドホンにするか、`GATE_MIC_WHILE_SPEAKING=1`（相方が喋っている間はマイクを送らない。そのぶん割り込みは効かなくなる） |
| 話の途中で返事してくる | — | `VAD_SILENCE_MS` を 1000〜1200 に上げる |
| 召喚中に独り言へ答える | — | persona.md の「召喚と退去」を見直し、`npm run eval` で確かめる |
| 画面について見当違いのことを言う | `[obs] スクリーンショット失敗` が出ていないか | OBS の WebSocket 設定とパスワードを確認する。特定のソースだけ見せたいなら `OBS_CAPTURE_SOURCE` を指定する |
| チャットに反応しない | `[youtube]` のログ | `activeLiveChatId が見つかりません` なら、配信開始前か動画 ID の誤り。`403` ならクォータ超過か、API キーで読めない設定（下記） |

## 7. 既知の制約・未検証のこと

- **YouTube チャットの認証**：公開配信のチャットを API キーだけで読める前提で書いている（公式ドキュメントでは明記を確認できなかった）。403 で読めない場合は OAuth 認証に切り替える必要がある。
- **クォータ**：`liveChatMessages.list` は 1 回 5 ユニット、既定の上限は 1 日 10,000 ユニット。10 秒間隔のポーリングで約 2.7 時間ぶんになる。長時間配信するなら `CHAT_POLL_MIN_MS` を伸ばす。
- **料金の目安**（Standard tier、2026-10 時点）：聞く役（gemini-3.5-transcribe-live）は約 $0.009/分で、2 時間半で約 $1.4。答える役（gemini-4-argon、入力 $2・出力 $10 / 100 万トークン。12 月 1 日から倍）は、召喚中の発話 1 件あたり数セントの見込み（未実測）。要約（gemini-3.8-flash）は 1 回数セント以下。
- **返事まで 5〜6 秒かかる**（評価での Argon の平均。画像と VOICEVOX の合成でさらに伸びる）。
- **相方の声は聞く役に届かない**（届くべきでもない）。相方の返事は記録に入るので、文脈は保たれる。ただし割り込みで途中までしか読まれなかった場合も、記録には返事の全文が残る。
- **画面の解像度**：幅 960px（`FRAME_WIDTH`）なので、小さい文字は読めないことがある。

## 8. 開発

### テスト

```powershell
npm test                # 全テスト
npm run test:watch      # 変更を監視して再実行
npm run test:coverage   # カバレッジつき（行・分岐とも 80% 未満なら失敗）
```

- 外部サービス（Gemini、OBS、VOICEVOX、YouTube、ffmpeg）は偽物に差し替えて動かすので、ネットワークも API キーも要らない。偽物は [test/fakes/](test/fakes/) にある。
- テスト名は「能力 / 要件 / シナリオ」の形で、[openspec/](openspec/) の仕様と対応している。
- 実機・実 API での確認は、手動スモークテスト（`docs/smoke-test.md`）で行う。

### 仕様（OpenSpec）

```powershell
npx openspec list                              # 進行中の変更
npx openspec show baseline-stream-cohost       # 変更の中身
npx openspec validate --all --strict           # 仕様の形式チェック（CI でも実行）
```

### CI とブランチ運用

- GitHub Actions（[.github/workflows/ci.yml](.github/workflows/ci.yml)）で、Windows と Ubuntu の両方について `openspec validate` とテスト（カバレッジ閾値つき）を回す。
- main に直接コミットしない。作業ごとにブランチを切って PR を出し、CI が通ってからマージする。
