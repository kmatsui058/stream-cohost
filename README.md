# stream-cohost — 配信用 AI 相方

配信者のマイク音声と OBS の配信画面を Gemini Live API にリアルタイムで送り、返ってきた発言を VOICEVOX で読み上げ、OBS のブラウザソースで立ち絵（口パク）と字幕を出す。YouTube のライブチャットも読む。

---

## 1. 全体像

```
 ┌──────────── この PC ─────────────────────────────────────────────────────────┐
 │                                                                             │
 │  AG03MK2 ──(DirectShow)──▶ ffmpeg ──16kHz PCM──┐                            │
 │                              src/mic.js         │                            │
 │                                                 ▼                            │
 │  OBS ──(obs-websocket :4455)──▶ JPEG 2秒毎 ──▶ src/gemini.js ═══WSS═══▶ Gemini Live API
 │        GetSourceScreenshot     src/obs.js      ▲      │                (gemini-3.8-live)
 │                                                │      │ 出力の文字起こし（テキスト）
 │  YouTube Data API ◀──10秒毎ポーリング── src/youtube.js │                            │
 │                     （チャット）        │       │      ▼                            │
 │                                        └──▶ src/director.js  ← いつ何を渡すか／文に区切る
 │                                                       │ 1文ずつ                    │
 │                                                       ▼                            │
 │                       VOICEVOX ENGINE ◀──HTTP── src/speaker.js  ← 発話キュー        │
 │                       (:50021)          WAV ──▶      │                            │
 │                                                       ▼ WebSocket (:8787)          │
 │                       OBS ブラウザソース  public/overlay.html                       │
 │                         ・WAV を再生（→ OBS の音声ミキサーへ）                        │
 │                         ・音量で口パク、字幕表示                                     │
 │                         ・再生終了を {type:'ended'} でサーバーへ返す                  │
 └─────────────────────────────────────────────────────────────────────────────┘
```

外部に出るデータは **Gemini（マイク音声・配信画面・チャット本文）** と **YouTube Data API（チャット取得のみ）** の 2 つだけ。VOICEVOX はローカルで動く。

### なぜこの構成か

| 判断 | 理由 |
|---|---|
| Gemini Live API | 音声と映像をストリームのまま入れられ、発話区切りの判定（VAD）や割り込み検知もサーバー側でやってくれる。STT → LLM → TTS を自前でつなぐより部品が少なく、遅延も小さい。 |
| **Gemini の音声出力は捨てて、文字起こしだけ使う** | 現行の Live モデルはテキストだけで返す設定（`TEXT` モダリティ）に対応しておらず、音声でしか返せない。声を VOICEVOX にしたいので、`outputAudioTranscription` で届く文字起こしを使って読み上げている。生成された音声は課金されるが使わない。 |
| 画面は obs-websocket のスクリーンショット | 配信に出ている画面（プログラムシーン）を、そのまま「視聴者と同じもの」として渡せる。仮想カメラや画面キャプチャを別に用意しなくていい。 |
| マイクは ffmpeg | Node からマイクを読むネイティブモジュールはビルドが面倒。ffmpeg に生 PCM を出させて stdout で受けるのが一番トラブルが少ない。 |
| 再生は OBS のブラウザソース | 音を OBS のミキサーに直接入れられるので、仮想オーディオケーブルが要らない。立ち絵と字幕も同じページで出せる。 |

## 3. 1 回の発話で起きること

1. マイク音声は **常時** Gemini に流している（100ms 単位）。画面は 2 秒に 1 枚。
2. Gemini 側の VAD が「配信者が話し終わった」（無音 `VAD_SILENCE_MS` = 800ms）と判断すると、応答の生成が始まる。
3. 生成中、`outputTranscription` が細切れで届く。director が `。！？!?♪` と改行で文に区切り、1 文ずつ speaker に渡す。
4. speaker は受け取った時点で VOICEVOX の合成を始める（1 文目を再生している間に 2 文目を合成する）。
5. オーバーレイが WAV を再生し、終わったら `ended` を返す。返ってこなくても、尺 + 3 秒で次へ進む。
6. `turnComplete` が来たら、区切り記号のない残りの文字列も読み上げる。

**割り込み（バージイン）**：相方が喋っている間に配信者が 2 文字以上話すと（入力の文字起こしが届くと）発話を止める。生成中であれば Gemini からも `interrupted` が届くので、まだ読んでいない文も捨てる。

**自発発話**：最後に誰かが喋ってから 25〜45 秒（ランダム）経つと、`【合図】配信者がしばらく黙っています…` というテキストを Gemini に送る。persona.md で「【合図】は配信者の発言ではない」と教えてある。

**チャット**：新着は溜めておき、場が空いている（相方が喋っていない・生成中でない・配信者が 3 秒以上黙っている）ときに、最大 5 件を `【チャット】\n名前: 本文` の形でまとめて送る。溜められるのは最大 20 件で、それを超えた分は古い順に捨てる。

### Gemini セッションの寿命（重要）

- Live API の **1 本の接続は約 10 分で切れる**。切れる前にサーバーから `goAway` が届くので、即座に新しい接続を張り直す。
- 張り直すときは `sessionResumption` のハンドルを渡して、**会話の文脈を引き継ぐ**（ハンドルの有効期限は 2 時間）。
- 映像入りのセッションは、コンテキスト圧縮（`slidingWindow`）を有効にしないと 2 分で終わる。有効にしてあるので長時間でも続くが、**古い会話は徐々に忘れる**。
- 予期しない切断のときは 1→2→4…最大 30 秒の間隔で再接続する。ログには `[gemini] 切断 code=... reason=...` が出る。

## 4. セットアップ

### 4.1 インストール済みのもの

- Node.js 22（既存）
- ffmpeg 9.0（`winget install Gyan.FFmpeg.Essentials`）※ **PATH が通るのは、新しく開いたターミナルから**。VS Code ごと再起動するのが確実。
- VOICEVOX 0.25.2（`winget install HiroshibaKazuyuki.VOICEVOX`）。DirectML 版なので Radeon でも GPU で合成できる。**配信中は VOICEVOX アプリを起動しておく**こと（アプリが ENGINE を `:50021` で立てる）。
- npm パッケージ：`@google/genai`、`obs-websocket-js`、`ws`

### 4.2 音声の経路（前提）

- OBS のデスクトップ音声は **オフ**。AG03MK2 の TO PC スイッチは **INPUT MIX**（PC の再生音はマイク側に戻らない）。
- そのため、配信に乗るのは「マイク」と「OBS に明示的に追加したソース」だけ。相方の声は、ブラウザソースの「OBS で音声を制御する」経由で乗る。**このチェックを外すと、相方の声は配信に乗らない**。
- Gemini に届く音声もマイクだけ。ただしスピーカーで聞いている場合は、空気越しに相方の声が入る。

### 4.3 やってもらうこと

1. **Gemini API キー**：<https://aistudio.google.com/apikey> で発行する。
   - ⚠ 無料枠では、送ったデータが Google のプロダクト改善に使われる。配信画面とマイク音声が対象になるので、気になるなら課金を有効にして有料枠で使う。
2. **OBS の WebSocket を有効化**：OBS の「ツール → WebSocket サーバー設定」で「WebSocket サーバーを有効にする」にチェックを入れる。パスワードは「接続情報を表示」で確認する。（今は無効になっている）
3. **`.env` を作る**：`.env.example` をコピーして `GEMINI_API_KEY`、`MIC_DEVICE`、`OBS_WS_PASSWORD` を埋める。
   - マイク名は `npm run mics` で確認できる。今の環境で見えるのは `Line (2- Yamaha AG03MK2)` だけ。
4. **OBS にブラウザソースを追加**（相方を出したいシーンに）：
   - URL `http://127.0.0.1:8787/`、幅 1920、高さ 1080
   - ✅「OBS で音声を制御する」にチェック → 音声ミキサーに出てくるので、その「オーディオの詳細プロパティ」で、モニタリングを「モニターと出力」にする（自分のヘッドホンでも聞こえるように）
   - カスタム CSS は空にする（ページ側で背景を透明にしている）
5. **立ち絵**：`public/char/closed.png`（口を閉じた絵）と `public/char/open.png`（口を開けた絵）を置く。無ければ緑の丸が仮表示される。位置やサイズは overlay.html の `#char` の CSS で調整する。
6. **（任意）YouTube チャット**：Google Cloud Console で YouTube Data API v3 を有効にし、API キーを `YOUTUBE_API_KEY` に入れる。動画 ID は配信ごとに変わるので、`.env` に書くか、起動後に `v <動画ID>` で指定する。
7. **声の変更**：`npm run speakers` で ID の一覧が出る。`VOICEVOX_SPEAKER` に指定する。配信の概要欄に「VOICEVOX:キャラ名」とクレジットを書く（各キャラの利用規約に従う）。

### 4.4 起動

```powershell
cd ~\stream-cohost
npm run test:voice   # 任意：API なしで、声とオーバーレイだけ確認
npm start
```

## 5. 配信中の操作（起動したコンソールに入力して Enter）

| 入力 | 動作 |
|---|---|
| `p` | **一時停止／再開**。マイク・画面の送信をやめ、発話も止める。席を外すときや、見せられない画面を出すときに使う |
| `s` | 今の発話をスキップする（キューも空にする） |
| `t こんにちは` | テキストで話しかける（マイクの代わり） |
| `v <動画ID>` | チャットを読む配信を切り替える |
| `r` | Gemini に今すぐ再接続する（様子がおかしいとき） |
| `q` / Ctrl+C | 終了 |

**最速の緊急停止**：OBS で相方のブラウザソースを非表示にするか、ミキサーでミュートする（プロセスは動いたままで、配信には出なくなる）。そのあと `p` を押す。

## 6. トラブルシューティング

まず `logs/` の当日ファイルを見る。タグ（`[gemini]` `[mic]` など）で、どの部品の問題か分かる。

| 症状 | 確認すること | 対処 |
|---|---|---|
| 起動直後に `VOICEVOX に接続できません` | VOICEVOX アプリは起動しているか | アプリを起動する。`curl http://127.0.0.1:50021/version` で確認できる |
| `[mic] ffmpeg を起動できません` | 新しいターミナルで `ffmpeg -version` が通るか | ターミナルや VS Code を再起動する。それでも駄目なら `FFMPEG_PATH` にフルパスを書く |
| `[mic] ... Could not find audio device` | `npm run mics` の名前と `MIC_DEVICE` が完全に一致しているか | 名前をコピーし直す。USB を挿し直すと名前の番号（`2-` など）が変わることがある |
| 話しかけても無反応（ログに 🎤 も出ない） | `LOG_DEBUG=1` で `🎤` が出るか | 出なければマイクの問題（入力レベルやデバイス名）。出ているのに返事が無ければ Gemini 側の問題 |
| `[gemini] 切断 code=1008` | モデル名と API キー | 1008 は「このキーではそのモデルを使えない／設定が不正」。`GEMINI_MODEL` を確認する |
| `[gemini] 切断` が延々続く | reason の内容 | `r` で手動再接続する。直らなければ再起動する（再開ハンドルは捨てられ、文脈はリセットされる） |
| ログに 🔊 は出るのに音が出ない | 「オーバーレイ未接続」の警告が出ていないか | OBS のブラウザソースのプロパティで「現在のページを再読み込み」。音が出ないならミキサーとモニタリングの設定を確認する |
| 画面左上に赤字で `cohost: 未接続` | `npm start` が動いているか | サーバーを起動すれば 2 秒以内に自動で再接続する |
| 相方が自分の声に反応し続ける／延々しゃべる | ① AG03MK2 の TO PC スイッチが **INPUT MIX** か（標準の設定。LOOPBACK だと PC の音がマイクに混ざる）② スピーカーで聞いていないか（マイクが空気越しに拾う） | ① INPUT MIX に戻す ② ヘッドホンにするか、`GATE_MIC_WHILE_SPEAKING=1`（相方が喋っている間はマイクを送らない。そのぶん割り込みは効かなくなる） |
| 話の途中で返事してくる | — | `VAD_SILENCE_MS` を 1000〜1200 に上げる |
| 喋りすぎ／自発発話がうるさい | — | `IDLE_MIN_SEC`/`IDLE_MAX_SEC` を上げるか 0 にする。persona.md の文字数の指示を強める |
| 画面について見当違いのことを言う | `[obs] スクリーンショット失敗` が出ていないか | OBS の WebSocket 設定とパスワードを確認する。特定のソースだけ見せたいなら `OBS_CAPTURE_SOURCE` を指定する |
| チャットに反応しない | `[youtube]` のログ | `activeLiveChatId が見つかりません` なら、配信開始前か動画 ID の誤り。`403` ならクォータ超過か、API キーで読めない設定（下記） |

## 7. 既知の制約・未検証のこと

- **YouTube チャットの認証**：公開配信のチャットを API キーだけで読める前提で書いている（公式ドキュメントでは明記を確認できなかった）。403 で読めない場合は OAuth 認証に切り替える必要がある。
- **クォータ**：`liveChatMessages.list` は 1 回 5 ユニット、既定の上限は 1 日 10,000 ユニット。10 秒間隔のポーリングで約 2.7 時間ぶんになる。長時間配信するなら `CHAT_POLL_MIN_MS` を伸ばす。
- **料金の目安**（gemini-3.8-live、Standard tier）：入力の音声が $0.005/分、映像が $0.002/分、出力の音声が $0.018/分。2 時間の配信で、入力だけなら約 $0.84。ここに相方が喋った分の出力が加わる。
- **会話は 1 本の連続したセッション**：配信者が喋るたびに Gemini は必ず何かしら返答しようとする。相づちだけで済ませる、黙るといった判断は persona.md の指示頼み。
- **相方の声は Gemini に届かない**（届くべきでもない）。Gemini は自分が生成した文として覚えているので、文脈は保たれる。ただし割り込みで途中までしか読まれなかった場合も、Gemini は最後まで言ったつもりでいる。
- **映像の解像度**：`MEDIA_RESOLUTION_LOW` + 幅 960px なので、小さい文字は読めないことがある。上げるとトークン（料金）が増える。
